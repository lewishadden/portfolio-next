## Doc notes (AGENTS.md / CLAUDE.md)

- **Wide layout rule.** Under `(min-width: 900px) and (min-aspect-ratio: 11/10)` page copy keeps to the left, leaving the right side to the camera's station framing (`clearRight`). New page content should follow the same caps:
  - stats, explore, recs and the contact column: min(46rem, 58vw);
  - the skills grid: min(48rem, 58vw), one card per row, `--span` classes neutralised;
  - the About grid: min(54rem, 58vw), name tag under the photo, highlights one per row under a 30rem bio column (container query on `.about__body`);
  - `.page-nav` aligns left.
  - Contact is one column at every width: intro, channels, form, map.
- **World windows** (`components/WorldWindow`, `[data-world-window]`): empty, aria-hidden spacers on home, About and Contact. They show only on narrow layouts when `html[data-world-expected]:not([data-world='off'])`. Otherwise they are `display: none`, which pageInputs ignores.
- **`[data-reading]`**: mark text that sits over the world. Use `data-reading="large"` only on headings: the measure also checks the real size. Keep each box tight to its text (`justify-items: start` on its grid parent), because the guard dims everything behind the box. A stretched heading measured the whole page width.
- **`data-world-target`** adds `contact:<name>` (contact cards) and `globe:home` (the LocationMap).
- **ScrambleText**:
  - `onFrame(shown)` reports the text on mount, then each decode frame from the decode's own animation frame. An effect on the displayed state lagged the DOM by a frame.
  - `scrambleGlyphs` is ASCII only. '-' and '/' let a decoding word break across lines, and the Greek letters fell back to a wider font, so the wrap and height changed mid-decode.
- **RoleRotator** stacks every title in one inline-grid cell; inactive titles are `visibility: hidden` and the caret is inside each title. The row keeps the tallest title's height, so on phones nothing below it jumps. It writes `worldStore.heroRole`.
- **useCountUp** (update the Custom Hooks entry):
  - It counts at full motion only.
  - It gives the real number until its count starts, never 0. The old version put "0+" in the DOM and the accessibility tree from hydration on.
  - StatsStrip hides the digits from screen readers and gives the value in an sr-only span.
- **Magnet**:
  - It responds to pointer events from a mouse only, needs `(hover: hover) and (pointer: fine)`, and works at full motion only. Touch's emulated mouse events used to leave tapped buttons pulled off centre.
  - It carries the plain `magnet` class, so `.magnet` page styles apply: `page.scss`, and the full-width hero CTAs at ≤640px in `Home.scss`.
- **Explore cards**: glass and spotlight paint on an inner `.explore__glass` layer, and the card is `preserve-3d` so the icon's `translateZ` lifts. Rule: never put `backdrop-filter`, `overflow: hidden`, `isolation` or `filter` on an element that must keep 3D children, because they flatten it.
- **Skill tiles**: a roving tabindex per category (one tab stop; arrows, Home and End; up and down go to the nearest tile in the next row). The level is the tile's `aria-describedby` (an sr-only "Proficiency N%" beside the tile). `:focus-visible` gets the hover styling, and `focusin` lights the badge through `useTargetHover`.
- **Testing note.** At calm and still, the global reduced-motion rule sets `transition-duration: 0.01ms !important` but leaves `transition-property: all`. Any style change (layout properties included) therefore transitions and only settles on the next rendered frame. With the world on at still, a script that injects CSS can read stale computed values. Inject `transition: none` with it.

### FX33: the explore icon now lifts (f28808b)

- **Cause.** The icon is not a direct child of the card. It sits in `span.explore__top`, which was still `transform-style: flat`, and `transform-style` is not inherited. The flat wrapper flattened the icon's `translateZ(30px)` into its own plane before the card's `perspective(900px)` tilt applied. My earlier check read the computed `matrix3d(..., 30, 1)`, which looks the same whether or not the icon is flattened, so it missed this.
- **Fix.** `.explore__top` is now `preserve-3d`, with a comment saying why.
- **Verification.** On the built home page, at 1440x900 and full motion, I hovered a card with a real mouse, so usePointerGlow tilts it. Then I compared the icon's bounding box with and without the translateZ (`/home/user/wi/scratch/l12/fix/fx33-page.mjs`):

  | `.explore__top` | Icon box with translateZ(30px) | Icon box without it |
  | --- | --- | --- |
  | preserve-3d (fixed) | 64.4x65.0 at (153.6, 296.8) | 62.3x62.8 at (160.2, 302.0) |
  | forced flat (as before) | 62.3x62.8 at (160.2, 302.0) | 62.3x62.8 at (160.2, 302.0) |

  With the fix the icon lifts. With the wrapper forced flat the two boxes are identical. A screenshot shows the glass and spotlight still painting behind the card content.

### FX36: up and down move a row (59bcbe3)

- **Cause.** `tileFor` worked out rows from `getBoundingClientRect()`, which includes transforms. The keyboard-focused tile is `:focus-visible`, which gets the hover lift (`translateY(-4px)`), so its row-mates looked like the next row down. This happened at every motion level.
- **Fix.** Rows now come from the layout offsets (`offsetTop`, `offsetLeft`, `offsetWidth`) of the tiles' cells, the `li` elements. The cells are siblings, so they share one offsetParent, and no transform moves these values: not the lift, not RevealItem's entrance offset, not the card's pointer tilt. Tiles count as the same row when they are within half a tile's height of each other.
- **Old code on the real page.** At 1280x720, with tile 2 lifted, the old logic sent ↓ to tile 1. The new code sends it to tile 7, and it still works with the card tilted the way the hook tilts it (`fx36-old-vs-new.mjs`).
- **Sweep** (`fx36-page.mjs`). I waited 600ms between keys, so the lift had settled, at full, calm and still:
  - 1440x900 and 1280x720 (5 columns): from tile 2, ↓7 ↓12 ↑7 ↑2 ↑2.
  - 390x844 (2 columns): from tile 2, ↓4 ↓6 ↑4 ↑2 ↑0.
  - ↓ on the last row stays put in every case.
- **e2e.** The roving-tabindex test in `tests/e2e/skills.spec.ts` now does the following:
  - works out the column count from the cells' `offsetTop`;
  - waits until the focused tile has its lift (`matrix(1, 0, 0, 1, 0, -4)`), so the test would catch the old bug;
  - asserts that ↓ goes to index + columns and that ↑ comes back;
  - asserts that End then ↓ stays on the last tile.

### Corrected doc notes (these replace the Explore and Skill tiles notes above)

- **Explore cards.** The glass and spotlight paint on an inner `.explore__glass` layer. The card is `preserve-3d`, and so is `.explore__top`, the wrapper between the card and the icon, so the icon's `translateZ` lifts it as the card tilts. Two rules follow:
  - `transform-style` is not inherited, so every element between a 3D context and the element that lifts must itself be `preserve-3d`. One flat wrapper drops the translateZ.
  - Never put `backdrop-filter`, `overflow: hidden`, `isolation`, `filter` or `opacity` below 1 on any of those elements, because they flatten too.

  To check a lift, compare the element's bounding box against a no-translateZ override. Its computed transform reads the same whether it is flattened or not.
- **Skill tiles.** Same as the earlier note, plus: ↑ and ↓ find rows from the cells' layout offsets (`offsetTop`/`offsetLeft`), never from `getBoundingClientRect()`. Screen rects include the focused tile's `:focus-visible` lift, the entrance offset and the card tilt, and the lift alone made ↓ move sideways.
- **About portrait.** Its `sizes` (`portraitSizes` in About.tsx) encodes the wide-layout widths from About.scss. Change both together.
