## Doc notes (AGENTS.md / CLAUDE.md)

### Projects ride (AGENTS.md, the `/projects` paragraph)
- **Snapping is directional.** Once a gesture ends more than 60px from where the scroll last came to rest (24px for a downward swipe from the top), it goes to the nearest stop beyond its start in its direction. Smaller gestures go back to the nearest stop. Using "nearest beyond the start" rather than "first stop past where it stopped" matters: a ride or fling that lands a little past a project, for example because web fonts shifted the layout after an index click, must stay on that project.
- **The HUD copy rides with the camera.** `Projects` writes `--ride` (`settleFocus(focus) - round(focus)`) and `--hud-o` (`clamp(1 - |ride|*2.2, 0, 1)`) on `.projects__stage[data-riding]`. Head, stack, summary and actions translate by `var(--ride) * -2.5rem` and fade, with no transition. Within 0.02 of a project the attribute and both variables are removed. Reduced motion keeps the fade only.
- **`data-docked` on the stage** (scroll between the first and last stop). In the stacked layout this hides `.back-to-top` (`body:has(...)`).
- **Narrow layouts** show the index as one sideways-scrolling row; `Projects` keeps the current link centred. Coarse pointers get 44px links.
- **Extra layouts:**
  - Short landscape (`max-height: 520px` and landscape): screen left with the index under it, copy right, actions beside the title, summary 2 lines.
  - Short portrait phones (700px tall or less): screen cell 30svh, summary 2 lines.
- **Clicking a helix screen** (page mode):
  - On `/projects`, the settled front screen opens the modal; any other screen dispatches `world:project` (`projectRideEvent`, detail = index) and `Projects` rides to it with `goTo`.
  - From other pages it opens the project page.
  - In tour or free roam it only pings.
  - Tips read "Open project" or "Ride to this project". They are stable objects per screen and action, swapped while hovered.
- **Closing a modal** for a project that isn't in front rides there and focuses its View details link on arrival (within 4s). Otherwise the link is focused if focus isn't already on the stage.
- **Gallery and screen stay in step.** The gallery writes `worldStore.projectShot` (`showProjectShot` also dispatches `world:project-shot`, so a world rendering on demand draws). The screens write `worldStore.screenShown`. Galleries open on `screenSlide(project)`, and the open gallery pins its screen: it loads the slide on demand, fades to it and holds it.
- **The ride emits `'tick'`** with the screen's position when it settles on a new screen, at every motion level.

### Project modal (AGENTS.md)
- **FLIP entrance.** With the world on, full motion and the project's screen in front, the gallery stage flies out of the front screen's projected rect (`worldStore.screenRect`, written each frame by `ProjectsStation` while `projectFocus >= 0`).
  - It uses the Web Animations API (FLIP, transform-origin 0 0), started in a layout effect so the first painted frame is already over the screen, and it ends at no transform.
  - Meanwhile the dialog's frame and copy fade in (`.pdm--flip`).
  - Close reverses it through `usePresence` (`.pdm--closing`). The close is undone if AnimatePresence brings the dialog back.
- **No backdrop blurs** (PF3): a plain scrim (80% of `--bg-primary`) and the dialog's own surface colour. The reason is the cost of blurring the live world every frame.
- **Phones.** The full-screen sheet (640px wide or less) reports `setChrome({ modalCover: true })` while open, so the world stops drawing behind it.
- **Title.** While open, `document.title` is `projectTitle(name) + ' | ' + siteName`. It is restored on close only if nothing has changed it since.

### Shots on the screens (AGENTS.md, World paragraph)
- **Accept header.** Image fetches send `Accept: image/webp,image/*;q=0.8` (`imageAccept` in `routes.ts`). The image endpoint varies its output on Accept: fetch's default gets JPEG, and a prefetch whose Accept differs from the decode's misses the cache.
- **Shared decodes.** `decodeImage` shares a decode already under way for the same URL and options. A shared bitmap must never be closed or transferred.
- **`ScreenShots` is made per effect run.** A disposed instance gives up its loads, and the old useMemo'd instance left every screen blank under StrictMode.
- **Sharp copies taller than 512 rows upload in 256-row bands** (`uploadBanded`):
  - a `DataTexture` with `source.dataReady = false` and declared mip levels, so three allocates the full chain with `texStorage2D` without generating mipmaps from the empty texture;
  - then one `copyTextureToTexture` band per frame, each booked through `queueUpload`;
  - the last band builds the mipmaps.
- **Sharp copies, and their prefetches, wait for the hub's hull** (or 6s at most), because they used to share its download.
- **Dev only:** the `projects:*` performance marks listed above.

### Station look
- **`ScreenArms`:** two InstancedMeshes in the truss material, matrices set once. They don't cast shadows, because an instanced depth variant would compile on the first shadow pass rather than with the station.
- **Screen shader:**
  - The next shot wipes down the screen behind a seam (`uSeam`).
  - `uPower` drives a power-up in the edge band: `power.tsx`'s charge curve compressed so the surge peaks at 0.6s. It flickers at most once a second (the three-flashes rule) and is 1 at `still`.
  - On a project page, screens other than the project's own that sit behind the heading (`worldStore.copy`) dim fully.
  - A project named on the page (`data-world-project`) lights its screen and makes it live.

- **PF4 leans on two things that should be rechecked after a three.js upgrade:**
  - WebGL2 sub-rectangle uploads from an ImageBitmap (`UNPACK_SKIP_ROWS` through `copyTextureToTexture`'s image path, taken because the source texture was never uploaded);

- **FX13 changes the snap rule.** The existing `@webgl` test asserted that 0.3 of a step glides back; I updated it so a 40px nudge glides back and 0.3 of a step carries on (commit a19ae2c). That is a deliberate behaviour change from the plan, not a weakened test, but please confirm.

- **Stale hover (pre-existing).** R3F only raycasts on pointer events, so a screen hovered before the camera rides keeps its tip until the pointer moves. With the tip swap it now reads "Ride to this project" for that screen. Calling R3F's `events.update()` while hovering during camera motion would fix it; I didn't do it here.

- **Arms.** They are thin dark rods that can cross the left copy area on the ride and on project pages.
- **`ProjectsStation.tsx` grew substantially** (the arms, shader, banded uploads, pins, tips, power-ups, ticks and instrumentation are all in one file). Worth a careful read.

### Doc notes (AGENTS.md, projects ride; replace the round 1 notes on snapping and the coarse index)

- **Snapping and catches.** A gesture is measured from where the scroll last rested, except when it catches one of the ride's own scrolls (a snap glide, or `goTo`'s ride from an index link, a helix screen or a modal closing). Those carry their destination in Lenis's `userData` (`rideTo`), which Lenis clears when they end or are taken over. A gesture that catches one is measured from the catch point, unless it keeps going the ride's way: then it is measured from where the ride was going (short of it, the ride goes there; more than 60px past, to the next stop). Bugs behind it: measured from the glide's destination, a short swipe onwards read as one back; measured from the catch point alone, a short one fell under the 60px commit and went back to the project the glide had just left; and rides from the index were never caught at all, so a swipe in a ride's tail was measured from before the ride. Any new programmatic ride scroll on `/projects` should pass `userData: { rideTo }` too.
- **Coarse index.** On coarse pointers every index link is at least 44x44. In the desktop column they sit two to a row (stage column `88px + 0.25rem`); in the stacked and short landscape layouts the index is one row. Don't size links to the stage: 15 at 44px in one column outgrow any stage under about 790px.
