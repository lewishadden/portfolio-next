# AGENTS.md

## Project Overview

This is a **Next.js 16** portfolio website built with **React 19**, **TypeScript**, and **SCSS**. Each section is its own route (`/`, `/about`, `/experience`, `/projects`, `/skills`, `/contact`, plus a page per project at `/projects/[slug]`) sharing a header and footer. Behind every page sits one persistent **WebGL world** (three.js via React Three Fiber) — each route is a "station" in space and navigating flies the camera between them. It uses server-side rendering with a Next.js API route for the contact form email endpoint.

The visual design ("Orbit" — dark sci-fi glow + light "daylight lab" theme) is documented in `docs/superpowers/specs/2026-09-24-orbit-redesign.md`.

## Tech Stack

- **Framework:** Next.js 16 (App Router)
- **Language:** TypeScript
- **Styling:** SCSS (BEM naming convention), CSS Modules (for select components)
- **3D:** `three`, `@react-three/fiber`, `@react-three/drei`, `@react-three/postprocessing`, `maath` (see `components/World`)
- **Fonts:** Unbounded (display), Geist (body), Geist Mono (labels), self-hosted variable WOFF2s in `app/_fonts` via `next/font/local` — don't switch back to `next/font/google`: its build-time fetch intermittently breaks Turbopack builds (see `app/_fonts/README.md`)
- **Icons:** `@iconify/react` with an offline bundle (`components/IconifyLoader/iconify-bundle.json`)
- **Forms:** Formik + Yup
- **Animations:** Framer Motion (`m` components under `LazyMotion` + `MotionConfig reducedMotion="user"`), CSS keyframes, Lenis smooth scroll
- **Linting:** ESLint, Stylelint, Prettier
- **Testing:** Playwright end-to-end tests (`tests/e2e`) with `@axe-core/playwright`; GitHub Actions CI (`.github/workflows/ci.yml`)
- **Package Manager:** npm
- **Node Version:** See `.nvmrc` (v24.x)
- **Email:** `nodemailer` via Next.js API route (`app/api/sendmail/route.ts`)
- **Geolocation:** `@vercel/functions` (used in `app/layout.tsx` to pass geo data to analytics)
- **Open Graph images:** `next/og`, one `opengraph-image.tsx` per route built on `app/_og/OgImage.tsx`

## Key Conventions

## Import Order and Grouping

All imports in TypeScript/JavaScript files must follow this order, with each group separated by a single blank line:

1. **External imports** (npm packages, e.g., `react`, `@iconify/react`)
2. **Internal JS/TS imports** (project files, e.g., `@/components/...`, `@/utils/...`)
3. **Type imports** (e.g., `import type { MyType } from '@/types'`)
4. **SCSS and CSS imports** (e.g., `import './Component.scss'`)

Each group must be separated by a newline for clarity and consistency.

## Prettier Formatting Rules

- All code must follow the formatting rules enforced by Prettier.
- Run `npm run prettier:check` to verify formatting and `npm run prettier:write` to auto-format code before committing.
- Do not manually override Prettier formatting; use the automated tool for consistency.

### Naming

- All variables, constants, and function parameters must use **camelCase** (e.g., `maxSliderHeight`, `paddingHeight`)
- Do **not** use `SCREAMING_SNAKE_CASE` or `snake_case` for any JavaScript/TypeScript identifiers
- Component names use **PascalCase** (e.g., `ProjectDetailsModal`)
- CSS/SCSS class names use **BEM** (`.block__element--modifier`)

### Component Structure

- Each component lives in `components/<ComponentName>/` with:
  - `<ComponentName>.tsx` — the React component (client or server)
  - `<ComponentName>.scss` — scoped styles using BEM naming (`.component__element--modifier`)
- Components marked `'use client'` are client components; otherwise they are server components.
- End-to-end tests live in `tests/e2e` (Playwright). `no-js.spec.ts` checks every route without JavaScript and with every script chunk failing (it imports plain `@playwright/test` where JavaScript is off: the fixtures' init scripts can't run). Import `test`/`expect` from `tests/e2e/fixtures.ts`, which seeds the theme and switches the 3D world off by default (`test.use({ world: 'on' })` to opt in). Open pages with `openHydrated()` before clicking anything client-side — a click that lands before hydration is a plain navigation. Tests that need real WebGL are tagged `@webgl` and run in the separate `chromium-webgl` project; don't add the SwiftShader flags to the default project (they make recent Chrome stall navigations for seconds). There are no unit tests.

### Styling

- Use **SCSS** with **BEM naming**: `.block__element--modifier`
- Theme variables are defined in `app/theme-variables.scss` as CSS custom properties on `[data-theme='dark']` and `[data-theme='light']`
- Reference theme values via `var(--variable-name)` (e.g., `var(--bg-primary)`, `var(--text-primary)`, `var(--accent-primary)`, `var(--surface)`)
- Gradient variables: `--gradient-start`, `--gradient-mid`, `--gradient-end`, and `--gradient-brand` (the ready-made violet → cyan gradient)
- Shared page system lives in `app/page.scss`: `.page`, `.page-head`, `.eyebrow`, `.page-title`, `.page-sub`, `.text-gradient`, `.glass`, `.spotlight` (pair with `usePointerGlow`), `.chip`, `.btn--primary` / `.btn--ghost`, `.page-nav`
- Inner pages start with `<PageHead>` (numbered eyebrow + title with gradient accent word); see `components/About` as the reference page
- Support both dark (default) and light themes; use `[data-theme='light'] &` for light-theme overrides
- Motion is a level, not a media query (see Motion levels under Important Notes): use `@include reduced-motion { … }` (calm and still) and `@include full-motion { … }` from `app/_motion.scss` wherever `@media (prefers-reduced-motion: …)` would go, nested in the rule they adjust or at the top level. They key on `html[data-motion]` and fall back to the OS query without JavaScript (no attribute); `:where()` keeps each rule's specificity. Inside the block `&` already carries the check on `<html>`, so use it at most once per selector. The global calm/still rule is in `app/globals.scss`
- Wide layouts (`(min-width: 900px) and (min-aspect-ratio: 11/10)`, the page system's wide layout, `isWideViewport` in `stations.ts`) keep page copy on the left so the station has the right side: stats, explore cards, recommendations and the contact column are capped at `min(46rem, 58vw)`, the skills grid at `min(48rem, 58vw)` (one card per row, the `--span` classes neutralised), the About grid at `min(54rem, 58vw)` (the name tag under the photo, and a container query puts highlights one per row under a 30rem bio column), and `.page-nav` aligns left. Contact is one column at every width: intro, channels, form, map. New page content should keep within these caps (the camera shifts the station clear of the widest `.glass` at the reading line, `worldStore.clearRight`). The About portrait's `sizes` (`portraitSizes` in `About.tsx`) encodes that block's widths (about `17.5vw - 22px`, capped at 236px from 1490px, split at 901px because the `max-width: 900px` block wins at exactly 900px): change the two together
- Text over the world carries `data-reading` (`data-reading="large"` on headings only): the hero's meta, greeting, name, role, tagline and HUD; each page head's eyebrow, title and sub; the About bio; the recommendations title and quote; the contact intro; the explore head; the projects ride's HUD (title, tech row, summary, site link) and index. The readability guard (see `Effects`) limits the world's luminance behind the six visible blocks nearest the reading line (a ceiling on the dark sky, a floor that lifts the light sky), so keep each box tight to its text (`justify-items: start` on its grid parent: a stretched heading measured the whole page width). Never put `--text-muted` inside a `[data-reading]` block: the guard can't hold it at 4.5:1 short of a black backdrop, so use `--text-secondary` there (the station readout and the hero HUD's stat labels do). Small text on glass or `hud-frame` panels uses `--text-secondary` or `--hud-text` too: `--text-muted` and `--accent-secondary` fall just under 4.5:1 on `--bg-secondary` in the light theme. On HUD text, blink a decorative part (a border, a dot), never the text's opacity; the light theme's `--signal` is `#92400e` for contrast
- 3D lifts in CSS (the explore cards: the glass and spotlight paint on an inner `.explore__glass` layer so the icon's `translateZ` lifts it as the card tilts): `transform-style` is not inherited, so every element between the 3D context and the element that lifts must be `preserve-3d` (the card and `.explore__top`); one flat wrapper silently drops the `translateZ`. None of them may have `backdrop-filter`, `overflow: hidden`, `isolation`, `filter` or `opacity` below 1, which flatten too. To check a lift, compare the element's bounding box against a no-`translateZ` override: its computed transform reads the same whether or not it is flattened
- HUD-style panels drawn in CSS (the command palette, the footer console) use the mixins in `components/HeaderHud/_frame.scss` (`hud-frame`, `hud-brackets`, `hud-caps`): opaque, never a backdrop blur. The loading screen's star tiles live in `app/_stars.scss` (`star-tile`, `tile-sizes`), shared with the world-off backdrop
- New controls are at least 44px to tap on coarse pointers (`(pointer: coarse)`): free roam's HUD, the tour card's buttons, the footer manifest rows, the projects index links; where the drawn control must stay smaller (the Hail pill in the readout line), an invisible 44px hit area surrounds it
- Inner scrollers get `data-lenis-prevent`; one that only scrolls sideways (the projects index row) gets `data-lenis-prevent-horizontal` instead, since plain `data-lenis-prevent` would hand vertical wheel input to native, unsmoothed scrolling. Overlays hold the page with `useLenisHold(active)` (`hooks/useLenisHold.ts`), never bare `useLenis()?.stop()` / `start()`: Lenis's stop and start aren't counted, so closing the palette over the mobile menu or the loading screen used to restart Lenis and scroll the page underneath them

### Custom Hooks (`hooks/`)

- `usePointerGlow` — sets `--mx` / `--my` on an element for the `.spotlight` glow, with optional 3D tilt
- `useCountUp` — counts a number up with cubic easing once it scrolls into view, at full motion only; below full it is always the real number. It returns the real number until its count starts, never 0 (it used to put "0+" in the DOM and the accessibility tree from hydration), and the server HTML (no JavaScript, crawlers) has the real number. `StatsStrip` marks the animated digits `aria-hidden` and gives the value in an sr-only span
- `useFocusTrap` — traps keyboard focus within a container (used in modals and mobile menu)
- `useMediaQuery` — subscribes to a CSS media query, SSR-safe
- `useMotionLevel` / `useMotionPref` (`useMotion.ts`) — the current motion level (`full` during SSR and hydration) and the visitor's choice (`system` included, for controls that show it), from `utils/motion.ts`
- `useReducedMotion` — `true` below full motion (calm or still), so it follows the visitor's choice as well as the OS; `false` during SSR
- `useLenisHold` — holds the page still (stops Lenis) while `active`, alongside any other holder, restarting it only when the last lets go; `holdLenis(lenis)` is the same for code outside a component (the project modal's scroll lock)
- `useRouteKey` — identifies the rendered route (layout segments), not the URL; key page transitions and scroll resets on it so shallow `history.pushState` URL changes don't trigger them
- `useScrollProgress(onProgress)` — hands scroll progress to a callback that writes the DOM directly; only `showBackToTop` is React state, so a scroll never re-renders
- `useWorldPreference` — `{ enabled, supported, setEnabled }` for the 3D world: WebGL/Save-Data support plus the visitor's persisted on/off choice (localStorage `world`). Support is a cheap check (no test context is created); `reportWebGLUnavailable()` flips it off when the canvas fails to start
- `useWorldFocus` — listens for clicks on 3D objects that stand for page content (skill badges, experience pods) and scrolls the matching `[data-world-target="skill:<name>"|"role:<index>"]` element into view with a `.world-ping` pulse. Only in page mode: in the tour and free roam such a click pings and plays its cue but leaves the hidden page's scroll alone, as project screens do

### Data Flow

- Content is loaded from `content/content.json` via `utils/serverUtils.ts` (`getPageContent()`)
- Page data is fetched in each `app/**/page.tsx` (server components) and passed as props to child components
- The root layout passes a small serialisable slice of content (`WorldContent` in `components/World/types.ts`: project slugs + up to four images each, tall full-page shots first, each with its width and its `index` in `content.json`'s images; skill icons, categories and levels (0..100, a string in `content.json`); roles with their company monogram (`initials`) and the `mission` number their card's patch wears; the About portrait; the tour's captions from `content.json` `tour`) to the 3D world, and a `PaletteData` slice to the command palette
- Project screenshots marked `"fullPage": true` in `content.json` are full-page captures, top of the page to its end, whatever their proportions (`isFullPage` in `ProjectBody`; the 3D screens scroll them too): the carousel shows them full width in a browser frame (`PageShot`) that pans down on its own (off for reduced motion, paused on hover, stopped for good once the visitor scrolls it) and scrolls by hand (`data-lenis-prevent`). A 2× screen gets them at most 2048 wide (`pageSizes` declares them a little under the 1066px they show at): the browser decodes a whole capture before it can draw its slide, and the full-size originals (up to 3024 × 8192) held up the frame after a click in the gallery for a quarter of a second
- `about.recommendations` in `content.json` are quoted verbatim from LinkedIn (`components/Recommendations`); keep the wording exact
- No client-side data fetching for portfolio content
- The contact form submits to `/api/sendmail` (Next.js API route) which sends email via nodemailer
- Project routes: each project in `content.json` has a unique `slug`. `app/projects/[slug]/page.tsx` is statically generated (`dynamicParams = false`). On `/projects`, each project's "View details" is a real link to `/projects/<slug>`; a plain click `history.pushState`s that URL and the modal opens from the pathname (`utils/projectPaths.ts`), so Back closes it and a refresh shows the full page. The modal and page share `components/Projects/ProjectBody`
- `/projects` is a ride down the 3D helix: a runway of scroll (`.projects__tour`, one `--step` of height per project, starting where the sticky stage docks under the header: project i is in front at `docked + step * i`) drives `worldStore.projectFocus` (a fractional index, settled on each project by `settleFocus` in `stations.ts` rather than stopping between two), and the camera rides the helix (`stationCamera`, case `projects`: it orbits down the spiral to face that screen, centred and large) while the helix itself holds still. A sticky stage holds the index (real links to every project page; a plain click scrolls the runway instead) and the HUD (`ProjectHud`): the project in front written round its screen (number, title and stack above, summary and actions below), swapped as the camera moves; nothing else on the page scrolls. At the top of the page the camera holds back on the whole yard beside the page head (`worldStore.projectIntro`, 1 at the top and 0 once the stage docks under the header; `projectIntro()` in `stations.ts`), so the first screen only comes forward, enlarges and lights up as the page scrolls, and its details (`ProjectHud`) stay hidden until the stage docks (`.projects__stage[data-waiting]`); off the page (touring past, flying in) the camera holds back too. Scroll that comes to rest on the ride snaps to a project, or back to the top (Lenis `scrollTo` after `snapAfter` ms of quiet, not while a pointer is down; any scroll input interrupts it), in the direction of the gesture (see the next point); past the last project scrolling is free, and the camera descends with the page (`worldStore.projectTail`, viewport heights scrolled past the last project, turned into a matching drop at the screen's distance), so the last screen scrolls away with its copy rather than sitting under the page nav and footer. Project pages set `worldStore.projectAside` so the camera sits the screen beside the copy instead, further back. With the world off (`html[data-world='off']`) the ride is the same (scroll, snapping and the index all work), but the HUD's middle shows the project's own screenshot, sized to fit the screen's cell, and the first project's details don't wait. Sticky needs no `overflow` other than `clip` on the page's ancestors
- The ride in detail (`components/Projects/Projects.tsx`):
  - Snapping is directional. A gesture is measured from where the scroll last came to rest. Once it ends more than 60px from there (`snapCommit`; 24px for a downward swipe from the top, `snapCommitTop`), it goes to the stop beyond its start, its way, that is nearest where it ended; smaller gestures go back to the nearest stop. Choosing the stop nearest where it ended, among those beyond the start, rather than the first one past where it stopped, keeps a ride or fling that lands slightly past a project (a web-font layout shift) on that project
  - The ride's own scrolls (a snap glide, or `goTo`'s ride from an index link, a helix screen or a closing modal) carry their destination in Lenis `userData` (`rideTo`). Lenis resets it when a scroll ends and replaces it on any later `scrollTo` (a smooth wheel's included), but a touch that takes over (syncTouch is off) only turns the scroll native, and `lenis.stop()` (a modal opening) leaves it too, so read it only while `lenis.isScrolling === 'smooth'`, as `riding()` and the `projectRideTo` listener do. A gesture that catches one is measured from the catch point (Lenis `virtual-scroll` while it glides); if it keeps going the ride's way, from where the ride was going instead: short of that, the ride goes there, and more than 60px past it, on to the next stop. A caught ride's heading is dropped as soon as one of the ride's own scrolls is seen running (a later ride from the index, Enter or a helix screen, or the caught ride itself when Lenis ignored the gesture), and by a mouse press (a scrollbar drag); a touch press keeps it, so a second swipe onwards in the momentum still counts from where the ride was going. Bugs behind this: measured from the glide's destination, a short swipe onwards read as a swipe back; measured from the catch point alone, it fell under the 60px commit and went back; index rides weren't treated as caught, so a swipe in a ride's tail was measured from before it; and a heading kept until the next settle sent a project picked from the index within about 1.4s of a caught swipe on to where the caught ride had been going. Any new programmatic ride scroll should pass `userData: { rideTo }`
  - A glide `goTo` sends also names its project in `worldStore.projectRideTo`, only when Lenis will really glide (full motion, Lenis not stopped or locked, not already there; `scrollTo` returns early otherwise, and a name left set would pull the camera ahead of the page). A Lenis scroll listener clears it as soon as the scroll under way is no longer one of the ride's own, and it is cleared while a project is open. The camera heads straight for it (`rideGoal`, see Camera); code that glides the runway more than a few screens must name its destination this way
  - The copy rides with the camera: Projects writes `--ride` (`settleFocus(focus) - round(focus)`) and `--hud-o` (`clamp(1 - |ride| * 2.2, 0, 1)`) on `.projects__stage[data-riding]`, and the HUD translates by `var(--ride) * -2.5rem` and fades, with no transition. Within 0.02 of a project the attribute and both variables are removed, so text at rest is crisp. Reduced motion keeps only the fade
  - Layouts: the stage gets `data-docked` between the first and last stop, which hides `.back-to-top` in the stacked layout. On narrow layouts the index is one sideways-scrolling row (`data-lenis-prevent-horizontal`) kept centred on the current project. On coarse pointers every index link is at least 44×44: two to a row in the desktop column (`calc(88px + 0.25rem)`), one row in the stacked and short landscape layouts; don't size links to fit the stage (15 links at 44px in one column outgrow any stage under about 790px). The stacked layout's media query includes `(max-height: 520px) and (orientation: landscape)` at any width; that short landscape layout puts the screen left and the copy right, actions beside the title and a 2-line summary (the camera frames the 3D screen in that cell, see Camera). Short portrait phones (700px tall or less) get a `30svh` screen cell and a 2-line summary. The desktop stage row is `minmax(0, 1fr)`
  - Helix screens answer clicks in page mode: on `/projects` the settled front screen opens the modal, and any other dispatches `world:project` (`projectRideEvent` in `ride.ts`, detail = index), which Projects answers with `goTo`; from other pages a screen opens the project's page; in the tour or free roam a click only pings. Tips read "Open project" or "Ride to this project". Closing a modal for a project not in front rides there (once the dialog's scroll lock has lifted) and focuses its View details link
  - The gallery writes `worldStore.projectShot` through `showProjectShot` (which also dispatches `world:project-shot`, so a world drawing on demand redraws), and opens on the shot the project's screen shows or is fading to (`screenSlide`, from `worldStore.screenShown`); an open gallery pins its screen to the gallery's slide
  - The modal's gallery flies out of the 3D screen: with the world on, full motion and the project's screen in front, its stage animates from `worldStore.screenRect` (which `ProjectsStation` measures each frame while `projectFocus >= 0`, the station is in range and the camera's ride (`riddenProjectFocus`) is within 0.02 of a screen, with all four corners in front of the camera; otherwise, mid-hop included, it sets `screenRect.on = false`) with a Web Animation started in a layout effect, so the first painted frame is already over the screen; the frame and copy fade in (`.pdm--flip`) and closing reverses it through `usePresence` (`.pdm--closing`). The dialog is opaque over a plain 80% scrim, no backdrop blur. As a phone's full-screen sheet it sets `setChrome({ modalCover: true })`, which stops the world drawing. While it is open `document.title` names the project (`projectTitle` in `utils/projectPaths.ts`, not `utils/seo.ts`, which would ship `content.json` to the client)

- What the newer specs cover: `motion.spec.ts` (the levels from localStorage `motion` and the OS setting, `html[data-motion]` before the app starts, the hero name's CSS letter rise only at full, a flight cut short by a level change still arriving, free roam flying at still, the footer and palette controls), `resilience.spec.ts` (storage blocked, a client navigation always showing its copy, analytics off for local and automated visits), `home.spec.ts` (key stats never read out a count from 0, the role line never moving the buttons under it), `palette.spec.ts` (rows with ranges and "Docked", no scroll under it, `sudo hire lewis` cancelled by every close, heading focus after a navigation, choosing a page from free roam), `space.spec.ts` (the readout and footer manifest, also without JavaScript, hailing, the scene line, haptics), `world.spec.ts` (`data-world-expected`, the world-off sky and renders, the tour's controls and closing card, leaving the tour for a page, focus coming back from the tour and free roam, free roam's keys, warming the next station on a phone, the phone stage framing), `projects.spec.ts` (directional snapping and its catches, the modal's tab title, closing a project away from the ride), `no-js.spec.ts` (world windows close at once on a clear failure, and never on a slow start), `mobile-menu.spec.ts`, `skills.spec.ts` (the roving tile group) and `header.spec.ts` (the loading screen docking into the logo slot)
- Testing gotchas: at calm and still the global reduced-motion rule sets `transition-duration: 0.01ms !important` but leaves `transition-property: all`, so any computed style change (layout properties included) settles only on the next rendered frame; with the world on at still a script that injects CSS can read stale values, so inject `transition: none` with it. Under SwiftShader headless, `getComputedStyle` mid-transition can be stale when no frames are drawn: take a screenshot to force one. To act on header chrome during a flight (the 3D toggle, header buttons) use `locator.dispatchEvent('click')`: `click()` waits for the swaying HUD bar to be stable, which it only is once the flight lands. The theme switch's role name is `Light theme` (`role=switch`). When picking palette rows by name, note that a project title starts with "Home"

## Accessibility

- **WCAG 2.1 Level AA** compliance is a priority
- Use semantic HTML elements (`<section>`, `<nav>`, `<header>`, `<footer>`, `<main>`)
- All sections use `aria-labelledby` pointing to heading IDs
- Interactive elements need `aria-label` when visible text is insufficient
- Decorative icons use `aria-hidden="true"`
- Forms must have proper labels, error messages, and validation
- Support keyboard navigation with visible focus indicators
- Use `.sr-only` class for screen-reader-only text (defined in `globals.scss`)
- Respect the motion level (`full`, `calm`, `still`; the OS's `prefers-reduced-motion` decides by default): nothing new may flash more than 3 times a second, at any level (the Hail button's cooldown, the global key toggles ignoring auto-repeat)
- `main#main-content` has `tabIndex={-1}` and no outline (`app/globals.scss`), so the skip link and code can focus it; the skip link is `inert` while the tour or free roam hides the page. `ThemeToggle` is `role="switch"` with the static name "Light theme" and `aria-checked`
- Text over the 3D world must reach 4.5:1 (3:1 large): mark it `[data-reading]` (see Styling) so the readability guard protects it
- Composite widgets get one tab stop: each skills category's tiles are a roving-tabindex group (arrows, Home and End; up and down go to the nearest tile in the next row, found from the cells' `offsetTop` / `offsetLeft`, never `getBoundingClientRect()`, whose rects include the focused tile's `:focus-visible` lift, `RevealItem`'s entrance offset and the card's tilt: the lift alone made ArrowDown move sideways). A tile's level is its `aria-describedby`, an sr-only "Proficiency N%"; `:focus-visible` gets the hover styles, and `focusin` lights its badge in 3D
- Anything that moves on its own holds while the visitor reads it (WCAG 2.2.2): the tour's countdown pauses on hover, keyboard focus in its card and its Pause button. When the tour or free roam hands back, focus returns to the control that started it (see Modes)

- `ThemeScript` runs as an inline script before hydration to prevent theme flash on page load. It also sets `html[data-motion]` (the saved motion level, else `still` when the OS asks for reduced motion and `full` otherwise) and, when the 3D world will run (not switched off, WebGL API present, no Save-Data), `html[data-world-expected]`, whatever the boot memory says, so pages keep room for the world (the phone world windows) from first paint; World sets it too if the world is switched on later. When it will run, the visitor isn't a crawler and the world hasn't loaded in the last 30 minutes (`bootMemory.ts`, localStorage `world-loaded-at`), it also sets `html[data-boot='loading']`, which shows the loading screen from first paint
- Motion levels (`utils/motion.ts`, DOM-safe): the visitor's preference (localStorage `motion`) is `system` (follow the OS's `prefers-reduced-motion`: `still` with reduce, else `full`) or a level of its own. `full`: everything moves, flights included. `calm`: the page holds its motion back (entrances only fade and de-blur in place, with no lift, offset, scale, arrival swing or page sweep, and the hero name's CSS letter rise, ScrambleText's decode and useCountUp's count are skipped; no sway, no magnet pull) and the camera cuts between stations instead of flying (no shake, no lightspeed, no tricks set off by the tour), but the world keeps rendering every frame, so its ambient life (twinkling, nav lights, slow spins, screens cycling, shuttles) carries on. `still`: nothing moves on its own and the world draws only on demand (what `prefers-reduced-motion: reduce` gets by default), except in free roam, where the visitor flies the camera and it draws every frame; the page's entrances still fade and de-blur in place, as at calm (Framer's `reducedMotion: 'always'` makes only positional and transform values, x/y/scale/rotate and width/height/top/left, instant, so opacity and filter still tween). `motionLevel()` is cheap enough to call every frame; `setMotionPref()` saves the choice (kept for the visit when storage is blocked), sets `html[data-motion]` and notifies `subscribeMotion` listeners, which also hear the OS setting change and another tab saving a choice. The OS setting is kept from its change events rather than read from the `MediaQueryList`, as Chrome drops a list's change event when its `matches` was read in between. Framer's `MotionConfig` gets `reducedMotion={level === 'full' ? 'never' : 'always'}`, and code asks `motionLevel() !== 'full'` where it used to match the media query. The choice is made from the footer's Motion control and the command palette (Motion: follow system, full, calm, still). Every new animation must be right at all three levels
- Loading screen (`components/BootScreen`, state in `components/World/boot.ts`, DOM-safe): on a full page load it covers the page while the world fetches its chunk, downloads models (counted through three's `DefaultLoadingManager`, hooked in `World/downloads.ts` when the chunk loads) and warms up (the warm-up tracker's task counts). `WorldCanvas` reports progress (`reportBoot`) and says when the first view is drawn with nothing loading or warming up (`readyBoot`); the bar fills and the screen lifts (`finishBoot`: `html[data-boot='leaving']`, stars streak past) into the camera's warp in, which `CameraRig` holds until then. Until it lifts the page is `inert`, Lenis is stopped, CSS animations under `#main-content` are paused, and `PageTransition`, `Reveal` / `RevealGroup`, `ScrambleText`, `useCountUp` and other in-view entrances wait (`useBooted()` / `whenBooted()`), so the page's entrance plays as the screen lifts. A skip button appears after a few seconds (it is in the server HTML, shown by a CSS animation delay, and works before React does through a delegated listener in `ThemeScript`, which also gives up on the screen at 25s if the app never starts), and `BootScreen` lifts it 20s from the page's start regardless. Once the app is running it also offers "Launch with sound" (a toggle, `aria-pressed`) unless sound was already on: the click turns sound on, so audio can start with the warp in; the screen still lifts on its own. Without the world it never shows and `useBooted()` is true once hydrated. Nor does it show within 30 minutes of the world last loading (`bootMemory.ts`: `World` notes the time once the canvas is ready, `ThemeScript` reads it), since everything is cached by then. Lifting at full motion, the big mark flies into the header's logo slot over 0.8s (`boot--docking`, offsets measured into `--dock-x` / `--dock-y` / `--dock-scale`; the screen's background is on `.boot::before` so it can fade separately), while `.header__logo-mark` stays hidden as long as `data-boot` is set and the header HUD powers on underneath (`header[data-hud-boot='docked']` skips the logo's own flicker-in; the HUD counts as away only while `data-boot='loading'`, not while leaving). Below full motion, leaving calls `clearBoot` at once. Its star tiles come from `app/_stars.scss`
- Sound (`components/Sound`): off by default; `SoundToggle` in the header, a command palette entry and the loading screen's "Launch with sound" turn it on, and the choice is remembered (localStorage `sound`; a returning visitor's sound starts on their first click or key press, as browsers require a gesture). Everything is synthesised with Web Audio, no files (`sound.ts`): a quiet bed (a low drone on A and a breath of cabin noise), a rush of filtered noise that follows `worldStore.velocity`, the header HUD's hum (`worldStore.hudHum`), and cues the world emits through `emitCue(cue, detail?)` in `worldStore.ts` (HUD blips, clicks in 3D (`ping`), tricks, hull bumps, stations powering up, the palette, the theme, autopilot, docking clamps, signals found, the rocket, the comms array transmitting, and since the immersion pass `tick` (the projects ride's detent: a relay click plus the projects voice's second note two octaves up), `pod` (the experience notes stepping down per role, `strength` = the role's index, emitted by `Experience.tsx` when `Math.round(worldStore.roleFocus)` changes, never on first draw), `sonar`, `scan`, `edge` (at most once a second), `hail` (squelch, chirp, then the station's chord) and `arrive`). A cue's `CueDetail` says where it happens (`at`) and how strong it is (`strength`). A cue with `at` plays through one of four pool panners placed there (`cueOut` in `spatial.ts`: HRTF on desktop, equal power on lite devices, inverse distance, full strength within 20 units, rolloff 1; the pool picks the panner that falls quiet first), while `hud-*`, `palette`, `theme`, `select`, `blip` and `arrive` always play centred. Emit world cues with `at`, and pass `spawnPing(…, { cue: false })` for a ping that only decorates another cue (a bump's ring, finds, the arrival ring), so it doesn't add its own click. Placed cues are heard relative to the camera, not the listener: below full motion and with the world off the listener glides for about 1.2s after the camera cuts, which put a cue at the station just cut to 60 to 100 units away, so `heardAt()` shifts each one by (ear - aim), and while a placed cue rings (`busyUntil`) its panner is re-placed every frame (a long one, the 4.3s launch, the arrival chime or a hail, used to drift away behind as the listener glided). Desktop only, a `ConvolverNode` with a procedural 1.8s stereo noise impulse that darkens as it decays takes sends from the pool and sonar panners; its wet level is 0.26 within 20 units of a station's voice and fades out by 55, so open space is dry. It is heard from the camera (`spatial.ts`): the listener follows `worldStore.camera` every animation frame while sound is on and the tab is visible (AudioParams, or `setPosition` / `setOrientation` where the listener has none, as in Firefox), and every station has a voice of its own where it floats: a soft chord through an HRTF panner (equal power on lite devices), breathing slowly, all drawn from A major pentatonic so voices that overlap stay consonant. The exponential distance model (full strength within 20 units, rolloff 1.9) keeps the docked station's voice in front and its neighbours faint, so a flight crossfades them and pans them as the camera turns; the derelict's detuned, warbling voice sounds on the 404 page and in free roam, fading in and out over 1.2s. `tune()` sets every voice's level each frame: while the world runs, a station that isn't fully powered (`worldStore.charge`: standby, or surging as it powers on) sings at its level × (0.2 + 0.8 × min(charge, 1.3)). With the world off the listener sits in front of the page's station and glides to the next. Flights (`onFlight`) add a swell as they set off (the warp in under the lifting loading screen too) and, on arrival, soft clamps and a chime in the destination's chord, played from the station. That needs a flight flown in: an `'end'` counts only if the last `'start'` was for that station and `worldStore.flight.progress === 1` (only `CameraRig` writes progress, setting 1 just before every arrived `'end'`; a flight dropped for free roam or by switching the world off emits no `'end'`). Any other `'end'` (a cut, tour stops below full motion) plays `arrive`, the station's chord an octave up; with the world off the sound engine's follow loop plays it when the address's station changes, never as the loop starts. Free roam's detector (`components/Sound/detector.ts`, DOM-safe) runs only in free roam while something listens: it pings from the nearest unfound signal (`nearestAt()` in `signalStore.ts`, the comet's live position included) every `lerp(2.4, 0.35, (bars - 1) / 4)` seconds through a dedicated panner (inverse, ref 40, rolloff 0.6), a ping gliding from 1.4 to 1.3kHz at level 0.02, and an echo of it 0.17s later at 0.3 of that. It schedules itself with a timeout of min(100ms, time to the next ping), so a gap isn't rounded up to the next check. A cue emitted while the context is still starting (just after the click that turned sound on) waits for it rather than going unheard. It suspends while the tab is hidden

The copy has no id, so the rule hiding `#main-content` doesn't hide it. - `World.tsx` (DOM side, in the root layout) decides whether to render: it sets `html[data-world='on'|'off']` (off for no WebGL / Save-Data / the header's `WorldToggle`, via `useWorldPreference`; `ThemeScript` applies a saved "off" before hydration), feeds scroll + pointer into `worldStore`, and lazy-loads `WorldCanvas` on `requestIdleCallback` so three.js never blocks first paint. An error boundary around the canvas is the real WebGL test: if the renderer can't start it reports the world unsupported. Switching the world off unmounts the canvas (`CameraRig` clears `worldStore.flight` as it goes, announcing nothing, so no flight is left active with its progress frozen). - `WorldCanvas.tsx` is the single `<Canvas>`: `Lighting` (a shadow-casting sun that follows the current station, which is the tour's stop in a tour and in free roam the station nearest the camera, the derelict included, and follows the camera itself in any mode while it is more than 40 units from that station, as on the far stretch of a flight or the warp in; hemisphere fill, violet bounce), the deep sky (`Nebula`, `Starfield` + `BrightStars`, `Landmarks`: planet, moon, sun flare; `Asteroids`; `Dust`; directions and placement in `sky.ts`), `GasClouds`, `Traffic`, stations, `Beacons` (glow + label for every station), `CourseLine`, `HeadingProjector`, `DockingBeam`, `EdgeShimmer`, `Pings`, `Effects` and `ThemeRetire`; after `CameraRig` and `ExploreControls` come `TipProbe`, `MotionProbe`, `Cockpit` and `Sparks`. Everything shown only later (free roam's ship, the docking beam, the edge, the course line) is mounted always and hidden, so it compiles in warm-up. The frameloop is `'never'` until warm-up finishes and while page chrome covers the world, `'demand'` at the still level except in free roam, and `'always'` otherwise. R3F restarts its clock at 0 whenever the frameloop changes, so `CoverPause` sets it back to where it stopped and asks for a frame (across a cover, and the still level's switches into and out of free roam or a change of motion level), dropping any frame R3F still had queued as the cover goes up (this leans on R3F 9.8 internals: `setFrameloop` zeroing `clock.elapsedTime`, `internal.frames`, and a "never" frame setting the clock from its timestamp; recheck after upgrading). At still, `DemandDriver` repaints on scroll, resize and route changes and asks for a second frame on the next animation frame, since `pageInputs` may measure after the first. `MotionProbe` (mounted after `CameraRig` and `ExploreControls`) measures how the camera moved each frame (`cameraMotion`: velocity, speed, the point on screen it is heading for and how much of its motion is into the view; snaps and teleports never count), for everything that follows motion; `PowerDriver` runs the stations' power (`power.tsx`). `QualityGovernor` mounts a drei `PerformanceMonitor` to move between quality tiers (`quality.ts`: DPR, bloom scale and the other per-tier costs, see `Effects` below), but its verdicts only count once nothing has warmed up and the camera hasn't flown for a whole judging window (and never while the canvas draws on demand), so loading work never reads as a slow device. The monitor stays mounted for the canvas's life so its history survives; a fall straight after a rise (within two judging windows) three times stops it rising, and a pause (a cover, a frameloop change, the tab coming back) is marked so its one long frame doesn't count. Tiers are `ultra | high | medium | low` (`html[data-world-tier]`). Lite (touch / narrow) devices start and top out at medium, desktops start at high. Ultra renders at 2x with bloom at 0.6 of it, only on desktops with `devicePixelRatio >= 2` whose canvas at 2x stays within 4.5M pixels (1280×800 fits, 1440×900 doesn't); it is reached only by an incline from high, a resize that no longer fits steps down at once, and the first fall from ultra caps the session at high (a module flag that outlives switching the world off and on). `Effects` builds three passes, the same on every tier, so a tier change never rebuilds the composer, recompiles a shader or shifts the exposure (a tier that dropped bloom read as the whole world flickering between bright and dim): bloom; then the optics, the tone curve, the reading guard and the vignette on the bloomed, still unclipped frame; then SMAA on the finished image and film grain. It builds the chain once: `themeChain` retunes bloom's intensity and threshold, the vignette, the knee and the grain in place on a theme change, and pass keys never carry the theme. The optics (`optics.ts`, one convolution effect, a single texture read at rest): while the camera travels (a flight, the tour's and the warp in's included, or free roam; eased out over 0.3s) and at speed, a radial streak blur out from the point the camera is heading for (the jump to lightspeed, from 40 units/s, full at 140, only moving into the view) with colour fringes towards the edges, its reach 0.55 on the light sky; scroll-driven camera moves never streak (End on a long page used to hit 124 units/s and kick into lightspeed). Light shafts fan from the sun when it is on screen (dark sky only). The reading guard (`ReadingGuardEffect`, inside pass 2 on every tier, no new pass) limits the world's luminance behind up to six `[data-reading]` blocks (`readingRects` / `readingLarge` / `readingCount`, feathered 40px) to keep their text at 4.5:1 (3:1 large) plus 3% headroom for the vignette and grain: on the dark sky a ceiling from the dimmest light text colours (`#a78bfa`, and `#818cf8` for large headings), scaling RGB so the hue holds; on the light sky a floor from the lightest dark text, `#0e7490`, scaling up where the colour has room, then towards white. It holds only while the page's copy is really on screen (`pageCopyShown()`: page mode, and not while a flight to a new page holds its copy back), so it lets go during a cruise and outside page mode but holds through the warp in, and a new guard starts firm. `--text-muted` isn't covered (see Styling). The limits are constants in `optics.ts` (`guardLimits`): update them if the theme's text tokens change. The tone curve (`HighlightRolloffEffect`): colours below a knee are left exactly as they are (0.88 dark, 0.96 light, so the screens and UI colours keep theirs), highlights above it roll off smoothly instead of clipping, and light too hot to show desaturates towards white, so glowing cores read as hot rather than as flat, saturated discs. The renderer itself isn't antialiased (`antialias: false`, no multisampling): SMAA (medium) is what keeps thin rings, trusses and orbit lines from shimmering. Grain is laid on in roughly perceptual space (it also dithers the sky's long gradients). Tiers differ in cost only: pixel ratio, bloom's internal resolution (`tierSettings.bloomScale`: a quarter on low, 0.6 on ultra, set through the effect), fringes, sun shafts and the heading projector's cone (high and ultra only), and the gas cloud and shuttle counts (half on low). @react-three/postprocessing turns the renderer's own tone mapping off, so `toneMapped: false` on a material does nothing: the curve above is the only one. Project screens are displays, not lamps: bloom leaves them out, so shots show at their own colours and brightness while the light round each screen's edge still glows. Each screen carries an invisible `ScreenMask` in its plane, just inside the edge light, on a layer only the bloom's depth pass draws (`bloomMask.ts`); `Effects` runs an inverted `SelectiveBloomEffect` whose selection follows the masks on show, so with the projects station out of range it skips its mask passes. Mask anything else that should keep its own brightness the same way (`maskBloom()`). The screen in front (`uFocus`) is solid with faint scanlines. On the projects page (or a project's), every screen loads a sharp copy of the shot it shows, and the screen in front one of the next as well, ahead of the camera (`ScreenShots.sharpen`), so no screen is ever soft once it is in front: as wide as the screen will be on the canvas in front (`frontScreenWidth`, worked out from the layout rather than measured, up to 2048), nearest the project in front first, three at a time, each prefetched at low priority so none waits on the network; flying in, they download and decode but hold their upload until the camera lands (`landed`). Copies of shots a screen has moved on from are dropped. Every screen keeps a 640px working copy. Shots are fetched at the next width the image endpoint serves and decoded in a worker (`imageDecoder.ts`: `createImageBitmap`, scaled to size and flipped there, never on the main thread) and uploaded one per frame (`queueUpload`): don't count on `/_next/image` to resize them, it can hand back the full-size original (up to 3024×8206), and uploading those stalled the first flight to the station for over a second. Shadows are decided once (off on lite devices): toggling them later would recompile every lit material
- Deep sky: `Nebula` bakes the sky once, in strips over several frames, into a half-float equirectangular texture (3072×1536 on desktop; lite devices ask for 1024 and get 2048×1024 where memory allows, `deviceMemory` unknown or at least 4 and `maxTextureSize` at least 4096, else 1024×512 with a warmer, dustier bulge, `uDetail`, as a magnified small bake blurred the band into a smooth grey); the dome samples it with a cubic filter and adds fine star grain at screen resolution where the bake's alpha says (a small repeating noise texture, two taps). The Milky Way is built in its own frame (`sky.ts`: `galacticNormal`, `galacticCentre`, `galacticEast`): a thin disc with faint wings, thicker and brighter towards the bulge, textured by star clouds and cut by filamentary dust lanes that absorb and redden what is behind them; noise for anything in the band is sampled with the across-plane axis stretched so features run along it. Nebulae are local: `sky.ts` `nebulae` lists the star-forming complexes (direction, radius, hydrogen-pink vs oxygen-teal) strung along the plane, one placed behind the stations for the pages' backdrop; each has a ragged outline, billowy gas with filaments, dust pillars in silhouette and a lit core. Keep the band's peak below the bloom threshold (`palettes.bloomThreshold`): above it bloom smears the whole band into a halo of fog. The same bake is filtered (PMREM) into `scene.environment`, so hulls reflect the sky they sit in. A same-sized placeholder environment is installed first so materials compile against the final shader variant. The bake itself is shared as a uniform (`skyMap` in `Nebula.tsx`) for anything that shows the sky through itself, bent (the home portal). Nearer in, `GasClouds` puts soft, wispy clouds of glowing hydrogen and oxygen beside the lanes between consecutive stations (44, 22 on lite devices, half of them on the low tier), so flights pass through and alongside gas with real parallax: camera-facing quads textured with a small baked noise tile, lit from the sun's side, fading as the camera comes close (no wall to fly through) and into the haze, never within 24 units of a station and, like the band, well under the bloom threshold. At speed the stars stream into streaks out from the point the camera is heading for (`Starfield`: one quad per star, round at rest, stretched in the vertex shader; `streakQuad` / `streakShape` are shared) and the near dust draws out into real motion trails along its path past the camera (`Dust`)
- Deep sky, the immersion pass:
  - Bake: one strip per frame, about 600k pixels on desktop and 250k on phones (eight strips for the 3072 and 2048 bakes); a strip costs its area (about 9ms per Mpx at five octaves) plus 1-2ms for binding the half-float target, and on an M3 Pro the whole desktop bake is about 40ms of GPU. The bake's size and octaves are decided once per canvas, like shadows (`Nebula` reads its `size` and `octaves` props only at mount): rebuilding the sky while the world draws (a desktop window resized across the 760px lite breakpoint) showed the new dome's unbaked target, black while the new program compiled and then filling in strip by strip, and left the hulls without reflections until the bake landed. One bake material and one environment kit (one persistent `PMREMGenerator`) last the canvas's life, compiled in warm-up. CLAUDE.md's shader NaN rule applies to the bake too: a NaN baked into the sky blacked out every frame with it in view, so clamp `0.5 + 0.5 * cos()` before `pow()`, and use `x * x` rather than `pow(x, 2.0)` for signed x
  - Theme change: the new theme bakes into a second target, the dome crossfades (`uMapA` / `uMapB` / `uMix`, 0.9s, at once at still), then the targets swap, `skyMap` moves to the new one, and the environment is rebuilt, the old map disposed a frame later. Disposing first left `scene.environment` on a deleted texture (black hull reflections for the whole bake), and a fresh generator per bake recompiled the GGX filter. A target being baked is never bound to a draw, even unread: it made ANGLE on Metal synchronise
  - The light sky has a broad gradient on galactic latitude, a warm sunward lobe, and the band as a soft ink wash that adds no light. A distant tilted spiral galaxy hangs at `sky.ts` `backdropDirection` (normalised (0.3, 0.12, 1)), behind the stations' cameras, seen flying back towards Home and in free roam; its core stays under the bloom threshold, and the light sky draws it as an ink wash
  - Warp: at `worldStore.velocity` 40 to 140 (eased) the dome dims the band and bulge to 45% where the bake's alpha marks them, and drops their grain (it smeared into a near-uniform grey at warp before)
  - Stars and dust: their streaks, and their swelling with speed, follow travel only (`travelAmount` in `Starfield.tsx`, the optics' test: a flight, the warp in and tour flights included, or free roam, eased out over 0.3s), never scroll-driven camera moves. Each star's radius is capped at 6 CSS pixels (`6.0 * uPixelRatio` in drawing-buffer pixels): free roam reaches 524 from the shell's centre and the shell spans 220-540 (squashed to 0.7 vertically), so the ship can fly into the shell, where a star a few units away drew as a disc hundreds of pixels across. Every station is framed looking the same way (-Z), so a flight is one of two manoeuvres. Ahead (the destination is roughly the way the camera faces): a cubic Bézier that climbs as it leaves, arcs over any station in the way and settles onto the destination's pose. The camera locks onto the destination station as it pulls away (`flightRotation`: the start view turns onto the station's centre, `lockOn`, over `lockTime` seconds, at most `lockShare` of the flight), then follows its bearing (eased by `lockFollow`, pitch held within `lockPitch`) so the station stays in the middle of the view as it grows, and from `settleFrom` settles into the viewing pose (which frames the same station beside the copy). The path arrives along the destination's viewing axis, so the bearing turns smoothly back onto the pose as the camera comes in. Across all 30 flights at desktop and phone sizes, ahead flights keep the destination within ~7° of centre mid-flight, peaking at ~123 deg/s. About-turn (the destination is behind): one sweeping cubic arc (`planAbout`) that bows out to the side the camera is coming from, passes the station on that side and curls round onto its front, coming in level with the pose from `curlOut` to the side. The camera turns to face the station as it pulls away (`departTurn`, the opposite way to how the arc later rounds it) and then follows the station's bearing (eased by `bearingFollow`, unwrapped frame to frame), so rounding the station turns the view back the other way onto its front: two opposite half turns, never a full spin, with the station in frame from the end of the first turn to arrival (it trails the bearing by at most ~11°). Timings are in seconds (`departTime`, `roundTime`); the speed profile builds slowly through the first turn and `planBrake` solves when to brake so about `roundReach` of the path is left, and slow, as the arc starts rounding the station. Peak turn rate across all about-turns is ~125 deg/s. Following a bearing is safe here only because the brake keeps the camera slow when it is close; anything that aims at a point should be eased and checked. Never aim the camera at a point on its own path or at fixed points from its moving position without a rate limit: that is what used to wobble and flip it round. When changing any of this, simulate every pair of stations (all 30 flights) for turn rate, total rotation and clearance, not just the one that looked wrong; the camera banks into heading changes in both manoeuvres.
